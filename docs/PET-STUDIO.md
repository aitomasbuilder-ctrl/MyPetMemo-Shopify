# Pet studio: personalized blanket, ornament and mug pages

The blanket product page lets a customer upload a pet photo, get an illustrated portrait, choose a
background, add a name, adjust the layout, pick a size, approve the preview and add it to the cart.
After payment the backend renders the print file from the approved design and creates a Printify draft order.

## How it fits together

```
Storefront (theme/)                         Backend (backend/, Vercel)                 Others
─────────────────────────────────────────── ─────────────────────────────────────────── ─────────────────────
photo ──► portrait worker /generate ───────────────────────────────────────────────────► Cloudflare worker
          (transparent pet, cached in the browser by photo hash; background, name and
           placement changes never call it again)
"Approve & add to cart"
   design JSON ──► POST /api/designs  ──► validate, id MPM-XXXXXXXXXX, HMAC-signed token
   /cart/add.js: variant + Design ID + preview (file) + _design (token) + _artwork (PNG file)
                                                                                      Shopify checkout
orders/paid webhook ───────────────────────► /api/orders-paid (answers at once, then in background):
                                              verify token (variant must match the line)
                                              Printify variant by SKU, exact print area from catalog
                                              download _artwork, check its SHA-256 against the token
                                              render full size (sharp), store (Vercel Blob), re-check
                                              Printify DRAFT order (external_id = Shopify order id)
                                              status in order metafield mypetmemo.fulfillment
                                              on any error: fulfillment hold + tag personalization-hold
```

* Preview and print use the same geometry (theme/assets/pet-studio.js `drawDesign`, backend/lib/render.js).
  All positions are fractions of the print area, so the preview is exact at any size.
* Pattern backgrounds are SVG generated by one file used on both sides:
  backend/shared/pet-backgrounds.js = theme/assets/pet-backgrounds.js (a test keeps them identical).
* Names are drawn with the same font files on both sides (Google Fonts in the browser,
  the same Fontsource builds in backend/fonts on the server). Accented letters are supported; emoji are not.
* Teeinblue is not used on this page: its widget cannot produce this layout, and the earlier AI test with it
  failed. It stays installed for any products that still use it.

## Ornaments

The same section runs the ornament pages (`templates/product.pet-ornament.json`, section setting
**Product type = Ornament**). The variant's shape option (Star, Circle, Heart, Snowflake) picks the outline:

* The preview, the cart preview image and the safe line are clipped to that outline. While adjusting, the
  part of the design outside the ornament stays faintly visible.
* The default layout puts the pet on the bottom edge (the outline hides where the portrait ends) with the
  name across its chest. Switching shape re-flows the layout until the shopper moves something.
* The print file is the full rectangular print area from Printify; the ceramic blank is pre-shaped.
* The outlines are drawn approximations of the blanks. Compare them with Printify's mockups and adjust
  `shapePath()` in pet-studio.js if a blank differs.
* Single-value options such as "One Size" are hidden.

Each ornament has its own template:

* `product.pet-ornament-christmas.json`: festive backgrounds (Christmas trees, snowflakes, twinkle lights,
  plaid, candy cane, winter snow, …) and an optional **year** line under the name.
* `product.pet-ornament-memorial.json`: soft clouds and watercolor backgrounds, optional **dates** and an
  optional **message** with suggestion chips ("Forever in my heart", …).

The extra lines (section setting **Extra text under the name**: none / year / memorial) are drawn under the
name in the same font, at half its size, and move with it. They travel in the signed design as `caption`
(`lines`, position, size), are rendered into the print file by `backend/lib/render.js`, and show in the cart
as Year / Dates / Message.

## Mugs

`templates/product.pet-mug.json` runs the same section with **Product type = Mug** (Printify *Accent Coffee Mug*,
11 oz and 15 oz, white outside with a colored handle and inside):

* The preview is a drawn mug. Its handle and inside take the color of the selected variant (the option whose name
  contains "Color"; known names such as Black, Navy, Pink, Light Blue map to a color, anything else shows white).
  The color option buttons get a matching dot, and 11oz / 15oz show as "11 oz · 325 ml".
* The design area is **one side** of the mug: half of the Printify wrap (`round(print width / 2)` by the print height).
  The same side is printed on both halves of the wrap (design `sides: 2`), so the mug shows the design in either hand.
  The handle sits at the wrap edges, so each side is centred a quarter turn from the handle.
* Styles: **Name below** (default), **Name on top**, **Big portrait** (large pet on the bottom edge, name across the
  chest). Picking a style re-places the pet and the text, like Reset.
* Section setting **Extra text under the name = One line of text** adds a free text line with suggestion chips
  (shown in the cart as Text). The cart line also shows *Printed on: Both sides*.
* Print file: the background covers the whole wrap. Patterns continue around the mug at the scale of one side;
  gradients and image backgrounds fill each side like the preview. Pet, name and text are drawn on each side and
  cropped to it (backend/lib/render.js).
* The cart image is a mug mockup of the approved design.

The Shopify mug product must come from Printify (so its variants carry Printify SKUs, which is how the backend finds
the Printify variant and the print area) and use the template suffix `pet-mug`.

## Pet portraits (wall art and digital download)

`templates/product.pet-portrait.json` uses its own section, `sections/main-pet-portrait.liquid` (family `portrait`),
with the same engine (`assets/pet-studio.js`) plus `assets/pet-portrait.js` / `.css`:

* Flow: upload → one AI portrait (the same worker as the other products) → choose **style**, **background color**,
  name, custom text, **size** and **frame** → live preview → **Approve my design** → **Add to cart**. Nothing is
  charged before checkout. Any change after approving clears the approval, so the cart always gets the approved version.
* Styles: Modern Minimalist, Watercolor, Classic Portrait (gold oval), Memorial Portrait (soft glow, name and dates).
  They are made in the browser from the one AI portrait, so switching style costs no AI request. The styled artwork
  is what gets approved and printed. Section setting *AI service paints each style* sends `style` to the worker
  instead (only if the worker supports it; each style is then its own AI request).
* Background colors are instant and never regenerate the artwork. `?bg=color/f4d9de` preselects a color.
* Preview: Close-up (framed), In a room (three rooms, drawn at true scale, so 8 × 10 looks small and 24 × 36 large),
  Before / after slider with the original photo, and Zoom (Fit, 2×, 3×).
* Variants: options **Size** and **Frame**. Frame values are read by name: *Black frame*, *White frame*,
  *Natural wood frame*, *Canvas, no frame*, *Digital download*. Sizes a frame does not come in are greyed out.
  Physical variants carry the Printify SKUs (framed canvas, gallery canvas); the print area and wrap come from Printify.
* Digital download: a variant whose SKU starts with `MPM-DIGITAL` (no shipping). The design is made at
  4800 × 6000 px (section setting). After payment the backend renders the file at full size, stores it in Vercel Blob
  and fulfills the line with the download link, so Shopify emails the customer (env `DIGITAL_DELIVERY=hold` only
  tags the order `digital-ready` instead). Orders with only digital items never create a Printify order.
* The cart line shows Style, Pet name, Custom text, Dates (memorial), Background, Frame/size and, for digital,
  *Delivery: Digital download, emailed after payment*.

## Reviews

Reviews come from the **MyPetMemo review** metaobjects (Shopify admin → Content → Metaobjects): name, rating
(1–5), review text, optional photo, optional product and optional order number. Only *Active* entries show.
The **Verified purchase** badge appears only when the order number is filled in. "Customer review" blocks on
the section are still supported. Product pages show:

* a star summary under the title (this product's reviews; if it has none, all MyPetMemo reviews, labelled as
  such; a reviews app's `reviews.rating` metafields win when present) that scrolls to the review cards;
* review cards below the product information (this product first; other products fill in when there are
  fewer than three, labelled "Review of …");
* the same reviews, one at a time, under the generation countdown.

With no reviews, nothing review-related shows on the live store. The theme editor shows clearly labelled
sample cards so the layout can be previewed.

## Generation progress

The loading section sits in the personalization column: spinner, "Creating your pet's portrait", the current
stage, a progress bar and an estimated countdown (section setting, default 60 s), then the review carousel
(or photo tips when there are no reviews). The bar never completes before the artwork arrives. Past the
estimate it says the portrait is taking a little longer. Cancel and failures keep the photo, name,
background and options, with Try again. Generation still times out after 180 s.

## Category pages

`/collections/pet-blankets` and `/collections/pet-ornaments` use `templates/collection.pet-category.json`
(section `main-pet-category`): one card per product with its image, price ("from" when sizes differ), sizes or
shapes with their prices, what the shopper personalizes, and a button to the product page. Unavailable
products show "Coming soon". The homepage blanket and ornament cards, the hero buttons and other
`product-link` uses open these pages (the Digital Pet Portrait card is unchanged). Collection sort order
decides the card order.

## Backend endpoints

| Endpoint | |
| --- | --- |
| POST /api/designs | Approves a design: validates it and returns `{ id, token }` |
| GET /api/print-template?sku= | Printify print-area size for a variant (cached a day) |
| POST /api/orders-paid | Shopify `orders/paid` webhook |
| POST /api/portrait | Pet photo (multipart `image`) → vector-style portrait on flat green (`{ image, background: 'chroma' }`), via Gemini. Needs `GEMINI_API_KEY` |
| POST /api/fulfillment-retry | `{ "order_id": 123, "force": false }` with `Authorization: Bearer $ADMIN_API_SECRET`; re-runs a held order |

Environment variables: see backend/.env.example. New ones: `DESIGN_SIGNING_SECRET`, `ADMIN_API_SECRET`,
`BLOB_READ_WRITE_TOKEN` (connect a Vercel Blob store), optional `STOREFRONT_ORIGINS`, `ALLOWED_ASSET_HOSTS`,
`GEMINI_API_KEY` (+ optional `GEMINI_IMAGE_MODEL`, `PORTRAITS_PER_HOUR`) for /api/portrait.

## Fulfillment states (order metafield `mypetmemo.fulfillment`)

`rendering` → `paid` (Printify draft created, `printify_order_id`, per line: design id, print size, file SHA-256,
print file URL) → `sent_to_printify` (only with `PRINTIFY_MODE=production`). `error` comes with a fulfillment hold
and the `personalization-hold` tag. Duplicate or concurrent webhooks never create a second Printify order
(metafield lock with compareDigest, plus Printify's own external_id check).

If the approval endpoint is unreachable, the storefront still adds the item with the design unsigned
(`_design_unsigned`); such orders are held for a manual check instead of being sent automatically.

## Checking it locally

`cd backend && npm test` runs the unit tests (design signing, rendering, two designs in one order,
duplicate/concurrent webhooks, artwork mismatch, render failure and retry, approval endpoint CORS).

## Matching add-ons before checkout (AOV upsell)

Shopify Basic can't add upsells inside checkout (Checkout UI extensions need Plus). So the offer is a modal on the
cart page that opens when the shopper presses **Checkout** with a personalized blanket or portrait in the bag
(`snippets/pet-upsell.liquid`, `assets/pet-upsell.js`, `assets/pet-upsell.css`, settings in the **Shopping bag** section).

- **Same pet, no re-upload.** When a blanket or portrait is added, `pet-studio.js` saves the approved artwork, photo,
  name/lettering, background and style in the browser (IndexedDB `handoff:<Design ID>`). On another device the offer
  rebuilds it from the cart line's uploaded `_artwork` / `_Original photo` files.
- Each add-on is laid out by the same engine (`MyPetMemoStudio.makeAddon`), signed by the same approval endpoint and
  added with the same line properties as on its own product page, plus `_MyPetMemo add-on`, `_MyPetMemo bundle`
  (the main Design ID) and a visible "Matching set" line. The order pipeline then renders one print file per line.
- No extra AI calls: the add-ons reuse the approved artwork.
- Anything failing (script missing, timeout after 8 s, network) sends the shopper straight to checkout. The offer is
  shown once per design per session.
- **Prices** are Shopify automatic discounts (no app, $0): "Matching add-on 15% off" (buy 1 from collection
  *Bundle main products*, get 1 from *Bundle add-ons* at 15%) and "Matching set 20% off both add-ons" (get 2 at 20%).
  Both are limited to once per order and don't combine with other product discounts, so the best one wins and they
  never stack with "Buy 2 ornaments". Collections are by tag: `bundle-main` (blankets, portrait) and `bundle-addon`
  (ornaments) or a title containing "Pet Coffee Mug". Change the percentages in **Discounts**, then the matching
  numbers in the Shopping bag section, Featured keepsakes text and Matching gift sets section.
- Homepage: `sections/matching-gift-set.liquid` ("Make It a Matching Gift Set"). Its example pictures
  (`assets/gift-set-*.webp`) were drawn by the studio engine from one golden retriever, so every piece shows the same
  pet; each can be replaced with an image in the theme editor.

## Large photo gallery (mug page)

`main-pet-studio` has two settings for a big product-photo gallery:

- **Large photo gallery** (`gallery_large`): the page opens on the first product photo with a swipeable row of
  rounded thumbnails underneath, previous/next arrows and swipe on phones. Once the shopper uploads a photo the
  preview shows their design again ("Your design" is the first thumbnail). Colors: cream, beige, caramel, cocoa.
- **Gallery photos from Files** (`photo_files`): file names from Content → Files, one per line, each optionally
  followed by `|` and the alt text. When filled they replace the product's own photos, so the gallery works before
  the product has media. The mug template uses the eight `mug-gallery-*.png` files.

Background swatches now include the brand pastels Blush Pink, Warm Cream, Beige, Sage, Pale Blue, Lavender and
Warm Taupe (`pet-backgrounds.js`, kept identical in `theme/assets` and `backend/shared`).

## Vector portrait style (AI)

`/api/portrait` asks Gemini (`gemini-2.5-flash-image`, about $0.04 per portrait) to redraw the shopper's own pet as a
clean flat-vector portrait: head and upper chest, same breed, markings, colors, expression and collar, on flat green.
The studio keys out the green and places the pet on the chosen pastel background, so switching backgrounds never
re-generates and the preview is the same artwork that is printed. To switch the store to it, set each studio
section's "Portrait generation URL" to `https://mypetmemo-shopify.vercel.app/api/portrait`.
